# ADR-0003: Фиксированное окно дедупликации от первого вхождения

**Язык / Language:** Русский · [English](./en/0003-dedup-window-semantics.md)

← [Все ADR](./README.md)

## Контекст

Требование R6: дубли за 5 минут схлопываются в одно. Нужно выбрать семантику окна —
фиксированную от `created_at` якоря или скользящую от последнего дубля.

## Решение

**Фиксированное окно**, привязанное к `created_at` уже существующего уведомления-якоря:
дубль в течение `DEDUP_WINDOW` после создания якоря инкрементирует `occurrences` и
обновляет `last_seen_at`, но не создаёт новую строку и не делает WS-push.

## Альтернативы

| Вариант                           | Почему отвергнут                                                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Скользящее окно от `last_seen_at` | Поток дублей каждые 4 минуты бесконечно продлевает жизнь одной записи — пользователь перестаёт получать новые уведомления |
| Уникальный индекс без окна        | Не закрывает «похожие события спустя время»; ломает легитимные повторы                                                    |

## Последствия

- Плюсы: предсказуемость для пользователя; поиск якоря ограничен по `created_at` → partition pruning.
- Минусы: два одинаковых события через 5+ минут — две записи (это осознанно).

## Триггер пересмотра

Если продуктовая семантика потребует «схлопывать, пока идут обновления одного orderId»
без верхнего предела — рассмотреть гибрид с жёстким TTL на якорь.
