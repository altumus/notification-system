# ADR-0004: Rate limit в PostgreSQL в той же транзакции

## Контекст

R5: не больше 10 уведомлений в минуту на пару `(user_id, type)`. Лимит должен переживать
рестарт процесса и быть консистентным при нескольких инстансах.

## Решение

Счётчик — `count(*)` по индексу `notifications_ratelimit_idx` внутри транзакции с
`pg_advisory_xact_lock(user, type)`. В окно попадают только **принятые** строки
(созданные); схлопнутые дубли и отклонённые попытки лимит не расходуют.

## Альтернативы

| Вариант                   | Почему отвергнут (на старте)                                           |
| ------------------------- | ---------------------------------------------------------------------- |
| Счётчик в памяти процесса | Обнуляется при рестарте; расходится между инстансами                   |
| Redis ZSET сразу          | Второй источник истины для ядра durability; усложняет локальный запуск |

## Последствия

- Плюсы: один источник истины (Postgres); гонки закрыты advisory-локом.
- Минусы: при тысячах RPS на горячую пару `(user, type)` count станет узким местом.

## Триггер пересмотра

При росте до тысяч RPS на одну пару — вынести горячий счётчик в Redis (Lua / ZSET),
оставив Postgres источником истины для принятых строк. Интерфейс `RateLimiter` позволит
подменить реализацию без смены контракта сервиса.
